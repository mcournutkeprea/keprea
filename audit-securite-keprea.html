À traiter en priorité

05
01

CORS grand ouvert sur les edge functions sécurité

Dans send-contact-email et send-field-feedback-email, Access-Control-Allow-Origin: "*" autorise n'importe quel site tiers à appeler ta fonction (spam, abus de ton quota Resend). À restreindre à https://www.keprea.com.

02

Validation serveur des entrées sécurité

Les edge functions insèrent et renvoient formData tel quel : pas de vérification de format email, pas de limite de longueur, et le message est injecté brut dans le HTML de l'e-mail (${formData.message}) — un input malveillant peut casser la mise en forme du mail ou tenter une injection HTML côté client mail.

03

Rate limiting absent sécurité

Aucune limite d'appels sur les deux fonctions Supabase : un script peut spammer le formulaire de contact et l'API Resend sans friction.

04

Aucune protection anti-spam sur les formulaires sécurité

ContactForm et FieldFeedbackForm n'ont ni honeypot ni captcha. Combiné à l'absence de rate limiting, c'est la porte ouverte aux bots.

05

Dépendances non scannées — 13 CVE haute sévérité sécurité

npm audit remonte 17 vulnérabilités (13 high) sur rollup, ws, postcss, yaml — et aucun CI n'existe pour les surveiller en continu. Un scan automatisé (Trivy ou simplement npm audit en CI) est le minimum utile ici, avant même Semgrep/Gitleaks/Nuclei.

Recommandés

06
·

CSP + en-têtes de sécurité complémentaires

vercel.json pose déjà X-Content-Type-Options, X-Frame-Options, Referrer-Policy et Permissions-Policy — solide base. Il manque une Content-Security-Policy et un Strict-Transport-Security explicite.

·

Scan du code — Semgrep

Utile pour détecter en continu ce type de faille (injection HTML dans l'e-mail, CORS ouvert) avant qu'elle n'atteigne la prod.

·

Détection de secrets — Gitleaks

Le .env est bien ignoré par git aujourd'hui, mais rien n'empêche un futur commit accidentel. Un hook/CI Gitleaks sécurise ça durablement.

·

Scan du site déployé — Nuclei/ZAP

Complément externe utile une fois les points ci-dessus traités, pour vérifier en conditions réelles (headers, endpoints exposés).

·

Images en WebP/AVIF

38 des 39 images de public/lovable-uploads sont en PNG — un seul fichier est en WebP. Conversion directement utile pour les Core Web Vitals et le SEO images.

·

404, liens cassés et formulaires testés

Aucune preuve de test automatisé (pas de CI). Un check de liens cassés + un passage manuel sur les deux formulaires avant la prochaine mise en prod reste pertinent.
